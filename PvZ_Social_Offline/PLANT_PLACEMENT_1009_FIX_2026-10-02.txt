PvZ Social Offline - Plant placement Error #1009 fix

Observed stack:
  BitmapUtil.drawMovieClip()
  BitmapMcManager.createBitmapDataForMc()
  BitmapMcManager.getBitmapDataFromApp()
  PlantBuilding.onGetPlantSwf()
  ResSwfManager.addSwfBlind()
  PlantBuilding.initSkin()
  Manager.putBuildingToMousePos()
  Manager.onClickBaseMap()

Root cause found in the project package:
- config.xml tells ResSwfManager to load the town plant SWFs from
  swf/20130627/town/plants/Plant_*.swf.
- Four of the supplied real plant SWFs were only present at the ZIP root:
  Plant_Peashooter.swf
  Plant_Sunflower.swf
  Plant_Repeater.swf
  Plant_SnowPeashooter.swf
- Therefore the client could receive a valid plant selection but the requested
  town SWF URL did not exist at the configured path. PlantBuilding eventually
  reached BitmapUtil.drawMovieClip() with no MovieClip and raised Error #1009.

Fix:
- Copied those four real SWFs into the exact paths already declared by
  config.xml. Cherry Bomb was already at the correct path.
- Verified all five usable town plant SWFs and their exported root symbols:
  Peashooter      -> TownPlant_Peashooter
  Sunflower       -> TownPlant_Sunflower
  Repeater        -> TownPlant_Repeater
  Snow Peashooter -> Plant_SnowPeashooter
  Cherry Bomb     -> TownPlant_CherryBomb
- Tightened server plant placement so a stale/unsupported seed without real
  town art is not accepted by the offline placement queue.
- Existing tutorial/adventure progression and plant-selection changes are kept.

Verification performed:
- server.py compiled successfully with py_compile.
- ZIP archive integrity checked with unzip -t.
- Configured five plant URLs exist and each SWF has a valid SymbolClass export.

Runtime Flash testing was not available here; the fix is based on the supplied
stack trace, project config, server data, and direct SWF symbol/path inspection.
