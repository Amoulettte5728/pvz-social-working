Almanac crash fix (Error #1009 in ComposeCardsContainer/setCardsWithPage)
=========================================================================
Build label: 2026-09-29-td-level1b-mcbutton-levelsave-almanac33

Cause
- The Almanac shows every <plant isDisplay="1"> in conf/PlantData.xml (38 plants).
- For each one it looks up the item config the server sends at login
  (propItemsConfigMap.get(plant id)), then reads .levelRequired, .money and .type from it.
- server.py built that item config from a hand-written list, _PLANT_ALMANAC_IDS,
  which had 37 ids. Blover (id 33, positionId 25, page 1) was missing.
- So the lookup returned null and the client crashed on opening the Almanac
  and on every page button (onPrevClickAct / onNextClickAct).

Fix (server.py only, no SWF changed)
- _PLANT_ALMANAC_IDS is now read from conf/PlantData.xml at startup: every
  isDisplay="1" plant id, in positionId order. The console prints
  "[ALMANAC] 38 displayed plants read from conf/PlantData.xml".
- If you show or hide plants in PlantData.xml later, the server follows
  automatically.
- The old hand-written list (with 33 added) is kept as a fallback in case the
  XML can't be read.
- Blover's card data already exists in GamePropItem_1_.xml (resourceId 33, 三叶草).

Tested (Ruffle, copy of this folder)
- Server startup: all five SWFs [OK], [ALMANAC] line printed.
- Town -> 强化 opens the Almanac. Page 1 shows 30 cards, with Blover at 25.
  Page 2 shows 8 cards (31-38).
- Next/previous pressed repeatedly in both directions: no errors.

Seen but not changed
- Position 29 (Ice-shroom, id 38) shows an empty card with price 0: no art and
  no price for it yet.
